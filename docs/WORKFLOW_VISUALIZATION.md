```
┌─────────────────────────────────────────────────────────────────┐

│                      (SQLite, ACID)                              │

  ┌──────────────┐       ┌──────────────┐       ┌──────────────┐
  │   SOURCES    │       │  DOCUMENTS   │       │    CHUNKS    │
  │   ────────   │       │  ─────────   │       │    ──────    │
  │ id (TEXT PK) │──┐    │ id (TEXT PK) │──┐    │ id (TEXT PK) │
  │ type         │  │    │ source_id FK │──┘    │ document FK  │──┘
  │ path         │  └───►│ version      │       │ ordinal      │
  │ checksum     │       │ checksum     │       │ text         │
  │ metadata     │       │ chunk_strategy│      │ token_count  │
  │ created_at   │       │ metadata     │       │ page_start   │
  │ updated_at   │       │ created_at   │       │ page_end     │
  └──────────────┘       └──────────────┘       │ char_start   │
                                                │ char_end     │
                                                │ section_path │
                                                │ embedding_idx│ ← FAISS
                                                │ bm25_doc_id  │ ← BM25
                                                │ metadata     │
                                                └──────────────┘

  Dedup Strategy:
  • Source: dedup by SHA256 checksum (unchanged files skipped)

  • Chunk: ordered by document + ordinal (UNIQUE document_id + ordinal)

## 6. Evidence Graph — The Knowledge Layer

### NetworkX MultiDiGraph Structure

```
┌─────────────────────────────────────────────────────────────────┐
│                    EVIDENCE GRAPH                                │
│                    (NetworkX MultiDiGraph → pickle)              │

  Node Types:
  ┌────────────────────────────────────────────────────────────┐

  │  ────────────── │  ───────────── │  ─────────────         │
  │  name, type,    │  subject, pred,│  description,          │
  │  aliases,       │  object,       │  participants,         │

  │  supporting_    │  chunks        │                        │
  │  chunks         │                │                        │
  └────────────────────────────────────────────────────────────┘

  Edge Types (8):
  ┌────────────────────────────────────────────────────────────┐
  │  SUPPORTS      │  chunk → claim (evidence for)             │
  │  CONTRADICTS   │  chunk → claim (evidence against)         │
  │  DERIVED_FROM  │  chunk → claim (origin)                   │
  │  MENTIONS      │  chunk → entity (reference)               │
  │  RELATES_TO    │  claim ↔ entity (association)             │
  │  INSTANCE_OF   │  entity → entity (type hierarchy)         │
  │  HAS_ASSUMPTION│  claim → claim (dependency)               │
  │  VALID_DURING  │  event → time_window (temporal)           │
  └────────────────────────────────────────────────────────────┘

  Query Pattern:
  ┌────────────────────────────────────────────────────────────┐
  │  GraphQuery → BFS traversal from start entities            │
  │  → max_hops, edge_type filters, temporal window            │
  │  → collect entities/claims/events/edges/paths              │
  │  → gather supporting_chunk_ids                             │
  │  → EvidenceStore.get_chunks_by_ids() → EvidenceRef         │
  └────────────────────────────────────────────────────────────┘
```

## 7. Verification Engine — The Contradiction Detector

### Rule-Based Contradiction Taxonomy

```
┌─────────────────────────────────────────────────────────────────┐
│                    VERIFICATION ENGINE                           │
│                    (Zero LLM Calls — Rule-Based)                 │
└─────────────────────────────────────────────────────────────────┘

  Input: list[Claim] from Evidence Graph
       │
       ▼
  ┌─────────────────────────────────────────────────────────────┐
  │  detect_contradictions() — O(n²) pairwise check             │
  │  ─────────────────────────────────────────────────────────  │
  │                                                             │
  │  For each pair (claim_a, claim_b):                          │
  │    │                                                        │
  │    ├── _claims_overlap()                                    │
  │    │   Same subject_entity_id?                              │
  │    │   Same object_entity_id?                               │
  │    │   Similar predicates?                                  │
  │    │                                                        │
  │    ├── 8 Contradiction Type Checks:                         │
  │    │   ┌────────────────────────────────────────────────┐  │
  │    │   │ PUBLICATION_DATE    │ same text, different date│  │
  │    │   │ METRIC_DEFINITION   │ same subject, different #│  │
  │    │   │ GEOGRAPHIC_SCOPE    │ same subject, different  │  │
  │    │   │                     │ geographic terms         │  │
  │    │   │ TIME_PERIOD         │ non-overlapping validity │  │
  │    │   │ REVISED_NUMBERS     │ different #, different   │  │
  │    │   │                     │ publication dates        │  │
  │    │   │ ENTITY_MISMATCH     │ different subjects,      │  │
  │    │   │                     │ similar predicates       │  │
  │    │   │ SOURCE_CONFLICT     │ same subject/predicate,  │  │
  │    │   │                     │ different sources        │  │

## 13. Key Design Principles

| Principle | Implementation |
|-----------|---------------|
| **LLMs are interpreters, not the database** | All evidence in SQLite/NetworkX; LLMs only generate/assess |
| **Fail-safe everywhere** | `_safe_structured_call()` never raises; fallbacks are deterministic |
| **Evidence-first rule** | Accumulated evidence never discarded on failure |
| **Deterministic short-circuits** | Budget limits, empty retrievals, simple queries avoid LLM calls |
| **Provider-agnostic gateway** | Custom `OpenAICompatibleProvider` base; swap providers via config |
| **Explicit model assignment** | `model_policy.yaml` controls all routing; no autonomous selection |
| **Fresh evidence wins** | Memory store supersedes older contradicting records automatically |
| **Provenance tracking** | Every chunk traces to source → document → file with checksum |
| **Cross-model verification** | Verifier uses DIFFERENT provider than synthesizer |
